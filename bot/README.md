# Telegram-бот Cubic Battle 4 (`bot/cb4_bot.py`)

Компаньон к игре: кубки раз в час, новости, заявки на премиум, админ-команды.
Хранит всё в локальной SQLite (`bot_data.db`), наружу ходит только в Telegram API.

## Запуск

```bash
pip install -r bot/requirements.txt
export CB4_BOT_TOKEN="123456:AA..."     # токен из @BotFather
python3 bot/cb4_bot.py
```

Токен **не** лежит в репозитории: бот читает его из `CB4_BOT_TOKEN` и без него
сразу выходит с подсказкой. Путь к базе можно переопределить через
`CB4_BOT_DB` (по умолчанию `bot_data.db` рядом с текущим каталогом).
Если токен когда-нибудь попадал в переписку или в публичный файл - перевыпусти
его у `@BotFather` (`/revoke`).

## Sanch и премиум

У игрока `Sanch` в игре **золотой ник** (`sanch_color = 0xFFFFD54A`,
`src/game/state/create/core/config_part2.inc`), поэтому в боте премиум у него
уже есть и покупать ему нечего:

* ник сравнивается без учёта регистра и пробелов (`admin_nick_equal` в игре,
  `nick_is_sanch` в боте): `Sanch`, `sanch`, `SANCH` - все считаются золотым ником;
* при старте бот прогоняет миграцию `UPDATE users SET premium=1, pending=0
  WHERE lower(nickname)=lower('Sanch')`, так что старые записи тоже становятся
  премиумными;
* премиум включается сам при регистрации, при смене ника и при входе в
  «Профиль»; в профиле пишется `📊 Статус: 💎 Премиум (золотой ник)`;
* в колонке `premium_src` видно, откуда премиум: `gold_nick` (за золотой ник)
  или `admin` (`/give`). Премиум за золотой ник снимается вместе с ником -
  иначе любой мог бы вписать `Sanch`, забрать премиум и сменить ник обратно;
  премиум от админа сменой ника не снимается;
* кнопка «💎 Премиум» отвечает «уже есть, ник золотой, платить не нужно»,
  звёзды не просит, заявку админам не создаёт;
* «✅ Я оплатил» для `Sanch` тоже ничего не отправляет - заявка не нужна.

Если нужно привязать золотой ник к конкретному Telegram-аккаунту (чтобы ник
`Sanch` в боте нельзя было вписать чужому), впиши его ID (узнать через
`@userinfobot`) в `SANCH_TG_IDS` в начале файла. Пустой список - премиум по
одному нику, как сейчас.

## Имена персонажа `буК`

Канон написания один и тот же в игре, в документации и в боте:

| Форма | Написание | Где |
| --- | --- | --- |
| Именительный (имя класса) | **буК** | `tr_class_ebuc()`, `locale_shop.inc` |
| Родительный («кого?») | **буКа** | «Подарок буКа», «Отскоки буКа» |
| По-английски | **ebuC** | `tr_class_ebuc()`, английский интерфейс |
| Притяжательное (англ.) | **ebuC's** | `ebuC's gift` |

Это не «Куб», не «Бук», не «EBUC» и не «ebuc»: `бу` строчными, `К` заглавная;
`ebu` строчными, `C` заглавная. Строки закреплены тестами
(`tools/test_game_state.c`, `tools/test_bot_sanch.py`) - при переименовании
тесты упадут.

## Проверки

```bash
python3 tools/test_bot_sanch.py
```

Тест поднимает временную SQLite-базу и заглушку `requests`: проверяет премиум
за золотой ник, отсутствие платежа и заявки для `Sanch`, ограничение по
`SANCH_TG_IDS` и канон написания `буК/буКа/ebuC/ebuC's`. Сеть не нужен.
