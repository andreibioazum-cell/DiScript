# ПК-версия Cubic Battle 4

В репозитории теперь две сборки одной и той же игры:

| | Android | ПК (Windows / Linux) |
| --- | --- | --- |
| Что запускается | APK | `CubicBattle4.exe` (Windows x64) |
| Графика | Vulkan | программный растеризатор (`src/platform/pc/pc_record.inc`) |
| Звук | AudioTrack через JNI | волновой вывод (waveOut) или тихий микс в харнессе |
| Сеть | HttpURLConnection через JNI | WinHTTP (Windows), сокеты (Linux-харнесс) |
| Ввод | касания | мышь как палец + клавиатура (WASD, ЛКМ - удар, E - блок, Q - суперудар, C - снежок) |
| Сохранения | `internalDataPath` | папка `cb4_data` рядом с exe |

Игра - это **те же самые исходники**: `src/game/game.c` (вся логика меню и боя),
`src/engine/runtime.c`, `src/engine/graphics.c`, `src/engine/network.c`,
`src/engine/audio.c`. Платформенный слой вынесен в `src/platform/pc`, поэтому
меню, бой, классы, ивенты и сеть ведут себя одинаково на телефоне и на ПК.

## Скачать готовый .exe

В GitHub Actions бандл `Cubic-Battle-4-PC-Windows` содержит
`CubicBattle4.exe` и папку `assets/` - распакуй их рядом и запусти exe.
Установка не нужна, Visual C++ Redistributable тоже не нужен: Zig линкует
рантайм в exe, из системного нужны только `WINHTTP`, `WINMM`, `USER32`,
`GDI32` - они есть в любой Windows 10/11.

## Собрать самому

Windows (собирается и на Linux, и на Windows):

```
pip install ziglang
python3 tools/build_pc.py --windows
```

Результат - `build/pc/CubicBattle4.exe` и `build/pc/assets/` (текстуры лежат
в корне, рядом папки `fonts/` и `sounds/` с подпапками `tracks/` и `sfx/` -
та же раскладка, что внутри APK).

Linux-харнесс без окна (тот же код, фиксированные кадры, BMP-скриншоты):

```
python3 tools/build_pc.py --linux
./build/pc/cb4_headless --assets build/pc/assets --frames 700 \
    --touch 220:360:686:0 --touch 223:360:686:1 \
    --touch 400:270:336:0 --touch 403:270:336:1 \
    --touch 460:270:404:0 --touch 463:270:404:1 \
    --stick 600:0:-1 --atk 620:1 --atk 640:0 \
    --report 650 --dump 690:/tmp/battle.bmp
```

Проверка одной командой (сборка + меню + бой + вход через подставную базу):

```
python3 tools/test_pc.py
```

## Управление

| Действие | Клавиши |
| --- | --- |
| Движение | `W` `A` `S` `D` или стрелки |
| Удар | `ЛКМ` - левая кнопка мыши, в любом месте экрана боя |
| Блок | `E` (удерживать) |
| Суперудар класса | `Q` |
| Новогодний снежок (при `Christmas: 1`) | `C` (кидает по направлению взгляда) |
| Три темы меню | кнопка «Тема» на экране «Играть»: Обычная → Новогодняя → Хэллоуин |
| Меню, логин | мышь; в поле ввода - обычная клавиатура, `Enter` - отправить, `Backspace` - стереть, `Esc` - закрыть |
| Чат в бою | мышь: маленькая кнопка чата и открытая панель кликаются как обычно, остальной экран - удар |
| Назад | `Esc` (в бою - выход из боя) |
| Скриншот | `F12` → `cb4_shot.bmp` рядом с exe |

Во время боя вся мышь работает как удар: случайный клик не может переставить
стик или попасть в кнопку выхода. Экран результата («нажми, чтобы вернуться»)
и чат онлайн-боя по-прежнему кликаются; выйти из боя можно через `Esc`.

### Кирпич буКа

Только у буКа ульта двойная: маленькая кнопка над ультой переключает деспенсер
(«Д») и кирпич («Ш»). В режиме кирпича нажатие на ульту запускает отсчёт 3-2-1
над кубиком; пока он идёт, палец (или мышь) тянет прицел в любую сторону арены,
и кирпич летит туда, отскакивая от стен. Отпустить палец можно сразу - 
направление остаётся. Удержаний в игре нет ни у кого: обычная ульта срабатывает
по нажатию. Кирпич работает и в онлайн-бою: полёт считается у всех одинаково от
точки броска, поэтому кирпич видно на чужом экране и он снимает здоровье тому,
в кого попал.

Клавиатура работает как виртуальный джойстик и нажимает те же боевые кнопки,
которые игра рисует на экране (`battle_render.inc`): ПК-ввод переводится в
касания (`src/platform/pc/pc_controls.inc`), поэтому в игре нет отдельной
«ПК-логики», которая могла бы разойтись с телефонной.

### Снежок, темы и авто-блок

Снежок при `Christmas: 1` - это тот же снаряд, что у буКа (радиус 24,
скорость 620, до 10 отскоков, взрыв радиусом 150), но урон всегда 0.5 и не
растёт от отскоков. Кнопка снежка размером с кнопку блока; если нажать не в
центр, а у края, снежок полетит в сторону этого края - то есть в любую сторону.

Одна кнопка на экране **«Играть»** (рядом с режимами боя, вместо старого
переключателя «Зимняя тема») переключает **три темы** по кругу: «Обычная»,
«Новогодняя» и «Хэллоуин» (оранжевая палитра, искры и собственная музыка).
В настройках этой кнопки больше нет. Надпись всегда показывает текущую тему,
выбор сохраняется в `settings.dat` (поля `style` и `chosen`).

Если выбрать «Новогоднюю», пока она недоступна (флаг `Christmas: 1` выключен),
кнопка остаётся **серой и выбранной**: игра честно показывает, что тема выбрана,
но рисует **обычную** тему - без снега, баннера, джингла и морозных цветов. Как
только админ включит `Christmas: 1`, та же самая выбранная тема оживает без
дополнительных нажатий. Снежки при этом всё равно выдаёт корневой флаг, а не
тема.

Два праздничных админа (`Dimasi4ek229`, `qwertyuiopaj1234`) видят Новый год
сразу, даже без флага - **пока сами не нажмут кнопку темы**. Их явный выбор
«Обычной» или «Хэллоуин» убирает только новогоднее визуальное оформление.
Когда глобальный `Christmas` включён, конфетное событие и Battle Pass доступны
всем онлайн-игрокам независимо от выбранной темы и аккаунта; снежки также
управляются глобальным флагом. Без интернета новогодний контент и события
недоступны, но тему Хэллоуина можно выбрать вручную; заработанные награды сохраняются.

`qwertyuiopaj1234` - полноценный второй админ: CCP-панель со всеми читами
(включая «Взлом H4c4k0r»), админ-команды чата (`/event 0..7`, бан и разбан,
смена пароля игрока), бесплатные классы и скины, колесо фортуны, полный
снимок базы и все инструменты веб-панели. Единственное исключение - **выдача
подарков**: вкладка «Подарки» в CCP, бесплатные стикеры в магазине и запись
чужих подарочных счётчиков остались только у `Dimasi4ek229` - правила базы
блокируют их даже через веб-панель. Забанить обоих корневых админов нельзя.

В CCP-панели администраторов появился восьмой чит **«Авто-блок»**: пока враг
в виндапе, игра сама ставит блок, а **после успешного блока бьёт врага
способностью**, а не обычным ударом. На Астре это именно её **фиолетовый блок**
(парри-щит): чит сам поднимает его нажатием супер-кнопки, а когда щит реально
поглотил удар и открыл «Захват», сам запускает этот удар-способность. У
остальных классов на виндапе поднимается синий блок, а после принятого удара
чит ставит в очередь их суперудар (рывок Азума, снежинка Санты, станция буКа,
оверклок CodeCracker). Пока способность ждёт своего окна, чит не мешает ей и
не размахивает кулаками; если окно закрылось - снова уходит в глухую защиту.
Между угрозами он поддерживает давление обычными ударами. Все читы, включая
его, помечают бой как «читерский» и отключают начисление кубков. Без интернета
все живые флаги (Christmas, AzumBuff, FlashSale, ивенты, баннер) сразу
сбрасываются - игра становится полностью обычной.

Девятый чит **«Взлом H4c4k0r»** запускает в бою глобальный ивент 7 - ту же
сцену, что веб-панель включает на всю комнату значением `event: 7`. Экран на
секунду накрывает глитч-помехами; игра смотрит, какое именно у тебя
устройство - других веток нет, игра выходит только под Windows и Android - и
ставит всё под него: на Windows хакер «подгружает» `hack/h4c4k0r.so` и
разводит консоли `C:\Windows\system32\cmd_0N.exe`, на Android -
`hack/h4c4k0r.bin` и shell-консоли `shell@kb4:/` (контейнеры готовит
`tools/gen_hack_payload.py`), - и читает из контейнера таблицу команд хакера. Дальше всё идёт по скрипту: три терминальных окна печатают диалог
H4c4k0r и Azum's посимвольно, у каждой строки свой кубик-аватар (красный у
хакера, цвета оригинального `azum.png` у Азума); его `/event 1` и `/event 2`
вылезают крошечными нерабочими заглушками, а несуществующие `/event 10` и
`/event 11` вырождаются в одно безобидное облачко в углу. На 0:40 с неба
сыплются кнопки меню - твёрдые блоки-укрытия, на которых можно прыгать; они
кликаются с родным звуком, но ничего не делают. На 1:15 прилетает бан:
терминалы краснеют, текст хакера стирается, а на 1:20 всё его хозяйство
взрывается, и Azum's досыпает ровно 10 новогодних тростей под 45 градусов -
каждая даёт конфеты, после чего раунд завершается чистой победой. Тайминги
сцены - только порядок действий, на экране они не рисуются.

### Разгон и торможение кубика

Стик (и `WASD`) сразу задаёт направление: кубик не уезжает по старой траектории
и не сносит в сторону. Меняется только длина скорости - она подтягивается к
цели за `walk_accel_time` (0.08 с), а отпущенный стик гасит её за
`walk_stop_time` (0.08 с), так что кубик коротко выкатывается и встаёт, а не
останавливается в тот же кадр. Оба числа - конфиг
(`src/game/state/create/core/config.inc`); и разгон, и торможение идут от
текущей скорости, поэтому время не зависит от частоты кадров.
Скорость сбрасывается при старте боя, на возрождении и когда кубик оглушён,
схвачен или летит после броска; в стену гасится только упёршийся компонент,
поэтому вдоль края арены кубик скользит.

## Где живёт ПК-слой

```
src/platform/pc/
  pc_main.c            цикл игры, хуки init/update/draw/touch, BMP-скриншоты
  pc_window.inc        окно Win32, GDI-блит, мышь и клавиатура
  pc_headless.inc      харнесс CI: кадры, сценарии касаний, отчёты
  pc_controls.inc      клавиша/мышь -> стик и боевые кнопки (касания)
  pc_args.inc          разбор командной строки
  pc_assets.inc        файлы ресурсов и лог (общие с Android API-имена)
  pc_record.inc        растеризатор: те же команды, что у Vulkan-бэкенда
  gfx_soft.inc         заглушки Vulkan-интерфейса поверх CPU-кадра
  audio_output_pc.inc  поток вывода звука (waveOut / тихий микс)
  network_http_pc.inc  http_ex()/http_stream() для WinHTTP и сокетов
  net_winhttp.inc      WinHTTP: https, keep-alive, ETag
  net_posix.inc        обычный http для харнесса (fake_firebase)
  keyboard_pc.inc      текст поля ввода, Enter, Backspace
  shim/android/*.h     подмена NDK-заголовков (assets, log, окно)
  pc_screenshot.inc    BMP для скриншотов харнесса
```

Рендерер повторяет конвейеры Vulkan один в один: те же команды
(`DS_CMD_RECT`, `DS_CMD_TEX_TINT`, `DS_CMD_TEXT`…), та же тесселяция в
`geometry.inc`, те же шейдерные формулы (`v_col * tex`, альфа-только для
tint), тот же nearest-сэмплинг и то же смешивание. Скриншоты ПК и телефона
поэтому совпадают по картинке, а `tools/test_pc.py` сверяет цвета известных
фигур по пикселям.

## Почему программы на ПК и на телефоне не разъедутся

* Логика одна: ПК вообще не трогает `src/game` (кроме моста
  `src/game/pc_pads.inc`, который только читает координаты кнопок).
* `tools/test_pc.py` гоняет настоящую игру: предупреждение -> лобби ->
  «Играть» -> «Соло» -> стик и удар -> бой, проверяет движение, урон и кадр.
* Второй прогон - вход в аккаунт через настоящий HTTP к
  `test/fake_firebase.py`: форма, Firebase Auth, чтение профиля
  (`cups=4200`), удержание сессии.
* CI собирает `.exe` на каждый пуш и прикладывает артефакт
  `Cubic-Battle-4-PC-Windows`.

## Ограничения

* Windows-бинарник собран через Zig: 64-битная Windows, exe без установщика.
* macOS не собирается (нет Cocoa-слоя); Linux - только харнесс без окна.
* В сети на ПК используется WinHTTP: прокси берётся системный, TLS -
  системный, поэтому корпоративные сертификаты работают как в браузере.
* Админ-команды в чате и модерация работают как на телефоне: это часть
  общей сетевой логики.
