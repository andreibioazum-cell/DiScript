# Текстурпаки: экспорт и импорт

Любой файл игры можно заменить своим: игра сначала смотрит в активный пак,
потом в папку `assets/`, и только в конце - во вшитую в exe копию. Поэтому
свой пак - это просто папка (или `.zip`) с файлами тех же имён.

## Быстрый круг: экспорт → правка → импорт

1. В лобби нажать **ПАКИ** (кнопка в левом верхнем углу).
2. **Экспорт** - игра соберёт `cb4_textures.zip` со всеми вшитыми текстурами
   и откроет системный диалог «куда сохранить» (на Android - обычный выбор
   документа).
3. Распаковать архив, перекрасить нужные PNG (размеры менять нельзя - движок
   рисует спрайты по пикселям).
4. Заархивировать обратно (годится любой zip без пароля) или просто оставить
   папкой.
5. **Импорт** → выбрать архив. Пак сразу включится, файл ляжет в
   `<данные игры>/packs/`.

Список паков - тот же экран: «Обычные» выключает пак, имя пака включает его
обратно. Выбор сохраняется в `packs/active.txt`, так что переживает перезапуск.

## Что внутри архива

Имена **плоские**, без папок:

```
TEXTURE_NAMES.txt
grass.png
ordinary.png
ordinary_punch.png
...
gift_bear.png
gift_cake.png
...
```

`TEXTURE_NAMES.txt` добавляется в каждый экспорт. В нём расписано назначение
всех имён: персонаж, стойка или удар, карточка магазина, предмет либо эффект.
**Имя файла определяет место спрайта в игре**, поэтому менять его не нужно.
Например, чтобы у Обычного куба был вид Деда Мороза, надо скопировать оба
файла: `santa.png` в `ordinary.png` и `santa_punch.png` в
`ordinary_punch.png`. `ordinary_gold.png` и `ordinary_gold_punch.png` - это
отдельный скин «Тыква», их для обычного куба менять не надо.

Так устроен загрузчик: он ищет файл пака по тому же короткому имени, которое
просит игра (`grass.png`), и только потом - по полному пути. Плоский архив
работает на всех платформах и не зависит от того, как распаковался zip.

Экспорт берёт **ровно то, что умеет игра**: 39 PNG (34 спрайта и карточки
классов + 5 подарочных стикеров) и `TEXTURE_NAMES.txt`. Звуки, шрифт и шейдеры
в пак не попадают - их можно заменить, но уже вручную, положив файл в папку
пака.

Импорт включает созданный пак, но не перезаписывает встроенные файлы игры.
Чтобы сразу вернуться к исходным текстурам, на экране «ПАКИ» выберите
«Обычные».

## Где лежит папка паков

| Платформа | Путь |
| --- | --- |
| Windows | `cb4_data/packs/` рядом с `CubicBattle4.exe` (или рядом с `--data`) |
| Linux-харнесс | `<--data>/packs/` |
| Android | внутренняя папка приложения, `packs/` |

Архив, положенный в эту папку руками, распаковывается при следующем запуске:
`mypack.zip` → папка `mypack`, и пак появляется в списке.

## Почему архив собирается в памяти

Экспорт пишет zip прямо в память (`pack_export_build` в
`src/game/core/packs.inc`), без временных файлов: на телефоне писать в
хранилище можно только через выбор документа, а на ПК это лишний шаг.
Ограничения: до 64 PNG и один файл `TEXTURE_NAMES.txt`, до 6 МБ архива,
каждый PNG до 1 МБ - реальный набор текстур занимает 3.6 МБ.

Записи хранятся **без сжатия** (метод `store`): так их читает и `zip_extract`,
и любой внешний архиватор, а PNG и так сжаты.

## Технические детали

* CRC-32 считается стандартным полиномом. Раньше `zip_crc32()` начинал с
  `RGB(255,255,255)` (0x00FFFFFF вместо 0xFFFFFFFF), и собранные нами архивы
  любой внешний распаковщик считал битыми - это исправлено, `tools/test_game_state.c`
  (`test_pack_export`) проверяет CRC через `zip_find` и читает `grass.png`
  обратно.
* `zip_build()` пишет заголовки в начало выходного буфера, поэтому данные
  пака лежат в **отдельном** буфере: `zip_build` теперь явно отказывается
  работать, если `out` пересекается с данными записи.
* Импорт создаёт все промежуточные папки (`packs_mkdir_parents`): до этого
  архив с подпапками молча не распаковывался.
* Список текстур берётся через `ds_asset_list()` (`AAssetManager_openDir`):
  на ПК shim листает папку `assets/` и **вшитое оглавление** exe, поэтому
  экспорт работает даже из одного бинарника без папки ресурсов.
* На Android экспорт асинхронный: системный выбор документа возвращает
  файловый дескриптор через несколько кадров, `pack_export_tick()` ждёт его и
  закрывает сам (или забывает запрос, если игрок передумал).

## Проверки

```
CC=gcc python3 tools/test_game_state.py     # test_pack_export + test_ambient_beds
python3 tools/test_pc.py                    # экран паков, клики, скриншоты
```

`test_pack_export` собирает архив из реальных `assets/textures`, проверяет
число записей, их имена, CRC каждой записи и совпадение `grass.png` с файлом
на диске.
