# MemTool (`memtool/`) — поиск и замена значений в играх на телефоне

Та же идея, что у [веб-панели админа](admin-panel.md): одна веб-панель без
сборки смотрит на живые данные, ищет значения и правит их на месте. Только
данные тут не Firebase, а **оперативная память запущенной игры** — что-то
вроде GameGuardian/Cheat Engine. Выбираешь игру с телефона, запускаешь,
цепляешься к процессу и ищешь/меняешь значения (монеты, здоровье, патроны)
прямо во время игры. Основной уклон — **Unity-игры** (IL2CPP и Mono).

Состав:

| Файл | Что это |
|---|---|
| `memtool/memtool.c` | демон на C: HTTP-API + сканер `/proc/<pid>/mem`. Один исходник собирается и на ПК, и под Android (PIE) |
| `memtool/panel.html` | вся панель одним файлом (как `index.html`), при сборке вшивается в демон |
| `memtool/fake_unity_game.c` | тестовая «Unity-игра»: фейковые `libunity.so`/`libil2cpp.so`, объект игрока с монетами и толпа двойников — как `test/fake_firebase.py`, только процесс |
| `tools/build_memtool.py` | сборка (`--host` / `--android`) |
| `tools/test_memtool.py` | сквозной тест: запуск игры через демон, скан, отсев, запись, заморозка, metadata |

## Сразу честно: нужен root

Читать и писать память *чужих* приложений Android без root не даёт
(ptrace scope) — точно так же, как GameGuardian. Варианты:

* телефон с **Magisk root**;
* **эмулятор** с root (AVD с google_apis + `adb root`, Genymotion и т. п.).

Без root панель честно покажет ошибку `EPERM` при подключении к игре.
Для *своих* отладочных нужд на ПК root не нужен: демон запускает фейковую
игру своим дочерним процессом, а потомков читать можно и без рута.

## Как запустить на телефоне

Собери Android-бинарники (нужен NDK):

```
python3 tools/build_memtool.py --android
```

или скачай `memtool-android.zip` из релиза `latest-build` (GitHub Actions
собирает `arm64-v8a`, `armeabi-v7a`, `x86_64` при каждом push). Дальше:

```
adb push build/memtool/android/arm64-v8a/memtool /data/local/tmp/
adb shell chmod 755 /data/local/tmp/memtool
adb shell su -c /data/local/tmp/memtool
```

Демон напишет ссылку вида `http://127.0.0.1:7766/?t=<токен>`. Способы открыть панель:

1. **С ПК (удобнее всего):** `adb forward tcp:7766 tcp:7766` — и ссылка из
   консоли работает прямо в десктопном браузере, пока игра открыта на телефоне.
2. **С самого телефона:** та же ссылка в мобильном браузере. Демон по умолчанию
   слушает только `127.0.0.1`, наружу ничего не торчит.
3. **Файлом:** панель — один HTML. Можно открыть `memtool/panel.html` любым
   браузером и вписать адрес демона + токен в секции «Подключение». Пригодится,
   если панель хочется держать на ПК, а демон слушает с `--host 0.0.0.0`
   (тогда панель видна по Wi-Fi — токен держи в секрете).

Токен обязателен для всех `/api/...`: демон работает от root и умеет писать в
чужую память, поэтому случайный сосед по Wi-Fi не должен до него дотянуться.

Фоновый режим на телефоне: `--daemon` (или `nohup ... &` в `adb shell`).

## Как пользоваться

1. В секции **«Игры»** демон показывает установленные приложения (`pm list
   packages -3`) и смотрит внутрь APK: есть `libunity.so`/`libil2cpp.so` —
   помечает карточку «Unity IL2CPP» или «Unity Mono». Кнопка **«▶ Запустить»**
   открывает игру (`am start` по главной активити, есть fallback на `monkey`),
   **«🎯 Прицепиться»** подключается к её процессу. Ниже — список всех
   процессов, если игра не нашлась автоматом.
2. В игре смотришь значение. Монеты = 1337 → секция **«Сканер»**: тип `i32`,
   значение `1337`, **«Первый поиск: точно»**.
3. В игре тратишь немного монет (стало 1330) → **отсев** «▼ уменьшилось»
   (или «= точно» с новым значением). Пару кругов — остаётся 1–3 адреса.
4. Клик по ✏ в результатах → **«Записать в игру»** — значение меняется сразу,
   без перезапуска. ⭐ добавляет адрес в **«Сохранённые»**, где его можно
   переименовать, менять и **замораживать** (❄: демон переписывает значение
   каждые 50 мс, панель можно закрывать).
5. **«Окрестность адреса» (👁)** показывает ±256 байт вокруг: поля одного
   объекта лежат рядом, поэтому вокруг монет обычно валяются здоровье,
   патроны и уровень. Клик по числу правит его.

## Чем помогает именно с Unity

* **Определение движка и версии.** По картам памяти демон видит
  `libil2cpp.so`/`libmono`/`libunity.so`, показывает базы модулей и выуживает
  версию Unity (`2022.3.15f1` и т. п.) прямо из `libunity.so`.
* **Пресеты регионов.** По умолчанию скан идёт по пресету «Unity IL2CPP:
  кучи + libil2cpp» — анонимные rw-регионы (там живут GC-куча IL2CPP и
  объекты) плюс дата-сегменты `libil2cpp.so` (статика). Это в разы быстрее и
  чище, чем «вся память». Для Mono есть отдельный пресет.
* **Адреса как `libil2cpp.so+0xXXXX`.** Такие сохранённые адреса панель при
  следующем запуске игры пересчитывает от новой базы модуля — ASLR не мешает.
  Работает для статических полей; адреса в куче (объекты) живут до перезапуска,
  панель об этом предупреждает.
* **`global-metadata.dat`.** В IL2CPP-игре имена классов и полей лежат открыто
  в этом файле внутри APK. Кнопка **«Стянуть из игры/APK»** достаёт его (демон
  ищет в картах памяти и через `unzip` из `base.apk`), панель парсит прямо в
  браузере: классы с их полями и поиск по именам. Не получилось автоматически —
  вытащи `.dat` из APK архиватором (`assets/bin/Data/Managed/Metadata/`) и
  загрузи через выбор файла. Зачем: знать, что поле называется, скажем,
  `_gold`, быстрее, чем гадать.
* **Объекты IL2CPP.** Кнопка «Объект с этого адреса» в окрестности помечает
  первые 16 байт служебного заголовка (указатель на класс + монитор на 64 бит),
  поля идут следом. «Найти указатели сюда» ищет, кто ссылается на объект
  (обычный поиск значения-адреса). «+Vector3» кладёт три `f32` в сохранённые.
* **Типы под Unity-привычки.** IL2CPP: счётчики обычно `i32`, здоровье и
  координаты — `f32`. Mono и старые игры часто держат деньги в `f64`.
  Строковые поля (ник игрока) ищутся типом «строка UTF-16».

## Подводные камни

* **Значение не находится.** Частые причины: игра держит его в `double`
  (попробуй `f64`), хранит отображаемое ×N, или защищает (XOR/шифр, как
  `ObscuredInt` в Anti-Cheat Toolkit). Тогда помогает «неизвестно (снимок)»
  и отсев «изменилось/не изменилось», но против шифра и это не всегда.
* **Онлайн-игры.** Валюта и прогресс живут на сервере — правка памяти ничего
  не накрутит, а античит может забанить. MemTool — для оффлайна, своего
  телефона и отладки своих же игр (CB4 на нём гонять можно и нужно).
* **Скорость.** Снимок «неизвестно» по всей rw-памяти большой игры — сотни
  мегабайт на диске демона (папка работы печатается при старте
  —`--workdir`). Сужай регионы пресетами.
* **32-битные игры на 64-битном телефоне** видны нормально (память читается
  как есть), только указатели у них 4-байтные — для «указателей сюда» выбери
  шаг 4 и тип `i32`.

## Демо и тесты на ПК (телефон не нужен)

```
python3 tools/build_memtool.py
build/memtool/memtool --demo-game "build/memtool/fake_unity_game /tmp/state.json --dir /tmp --tick-ms 1000 --dec"
```

Открыть напечатанную ссылку: в «Играх» появится «fake.unity.game», её можно
запускать и сканировать из панели. Игра каждую секунду тратит 3 монеты,
поэтому отсев «уменьшилось» находит монеты с первого раза; её правду
(адрес монет, значения) видно в `/tmp/state.json`, fake-game также владеет
статическим полем `static_coins` на `libil2cpp.so+0x8000`.

Сквозной тест (42 проверки: запуск через демон, IL2CPP-детект, скан/отсев,
запись в живую игру, заморозка, статика по модулю, `f64`, UTF-16 ник,
снимок+«изменилось», поиск указателей на объект, окно окрестности, раздача и
парсинг синтетического `global-metadata.dat` парсером панели):

```
python3 tools/test_memtool.py
```

Тест запускает игру именно через демона (демон — её родитель), поэтому
проходит и при `ptrace_scope=1`, в том числе в GitHub Actions (джоба
`build-memtool` дополнительно собирает Android-бинарники трёх ABI и кладёт
`memtool-android.zip` в релиз `latest-build`).

## API демона одной строкой каждый

Все вызовы требуют заголовок `X-Token` (или `?t=`): `/api/status`,
`/api/games`, `/api/processes`, `/api/launch` (`pkg` на Android, `cmd` —
только хост/флаг `--allow-cmd`), `/api/attach` (`pid`|`pkg`), `/api/detach`,
`/api/scan/first`, `/api/scan/next`, `/api/scan/reset`, `/api/results`,
`/api/write`, `/api/readmany`, `/api/freeze`, `/api/freeze/list`,
`/api/peeks`, `/api/unity/info`, `/api/unity/metadata`. Тела — плоский JSON;
панель (`memtool/panel.html`) — живой пример всех вызовов.
